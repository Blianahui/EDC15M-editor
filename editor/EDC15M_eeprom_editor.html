Builds an EEPROM image that both starts the engine (native immobiliser data) and is accepted for flashing by the programmer (donor's write-enable block). Everything runs locally in the browser; files are never uploaded.

Собирает образ EEPROM, который одновременно заводит двигатель (родные данные иммобилайзера) и принимается программатором на запись (блок разрешения записи от донора). Всё работает локально в браузере, файлы никуда не отправляются.

Scope: verified only for Opel Frontera B X22DTH, Bosch 0281001791, software UU2M6S90_S, EEPROM 24C04 (512 bytes). Область применимости: проверено только для Opel Frontera B X22DTH, Bosch 0281001791, ПО UU2M6S90_S, EEPROM 24C04 (512 байт). On a different ECU or software version the location of the write-enable block (and the other regions below) may differ and must be re-verified — do not trust these offsets blindly. This tool edits only the write-enable block (G3); it never changes the immobiliser data, so it does not help with bypassing an immobiliser. На другом блоке или другой версии ПО расположение блока разрешения записи (и прочих регионов ниже) может отличаться и его нужно проверять заново — не доверяйте этим смещениям вслепую. Инструмент меняет только блок разрешения записи (G3) и никогда не трогает данные иммобилайзера, так что он не помогает обходить иммобилайзер.

Why this works

Почему это работает

On this ECU the flash write-enable is controlled only by 20 bytes at 0x4C–0x5F (“G3”); the engine-start / immobiliser path never reads G3, and the programming path never reads the immobiliser block. So a native dump's immobiliser data and a donor dump's write-enable block can be combined freely, as long as both are internally consistent (triple-redundant values and the marker below). Full details, including what G3 is not (not a VIN, not a simple checksum, its tail byte isn't derived from the rest), are in the project's finding writeup.

В этом блоке разрешение записи флеша определяется только 20 байтами 0x4C–0x5F («G3»); тракт пуска/иммобилайзера G3 не читает, а тракт программирования не читает блок иммобилайзера. Поэтому данные иммобилайзера родного дампа и блок разрешения записи донорского дампа можно свободно комбинировать, если оба внутренне непротиворечивы (тройное резервирование значений и маркер, см. ниже). Подробности, в том числе чем G3 не является (не VIN, не простая контрольная сумма, хвостовой байт не выводится из остального блока), — в описании находки в репозитории проекта.

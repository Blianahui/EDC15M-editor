# Terrano 2.7 TDi — Bosch 0281001550 (EDC MSA 15.5), software 1037356022

256 KB flash image. Same hardware generation as the Frontera 0281001791 (two flash chips, C167 with mask ROM), and the same memory layout: the Frontera tools and findings transfer here much better than EDC15VM+ material.

Some listings label 0281001550 files as “Jeep Cherokee 2.7 TD” with Nissan numbers 23710-7F405; these are Terrano files under a different name. One listing gives the EEPROM as 24C02 — check on the board.

## Memory

The flash is mapped from CPU address 0, so **file offset = CPU address** in the 0x10000–0x3FFFF range.

| Addresses | Contents |
| --- | --- |
| 0x00000–0x0FFFF | mask ROM as seen by the CPU; calls `00:xxxx` go there |
| 0x00000–0x07FFF (file) | second dataset, Nissan 7F406 (see below) |
| 0x10000–0x13FFF | loader and services; 19-entry vector table at 0x10120 pointing into ROM (timers, ADC, serial port, reset) |
| 0x10000–0x37FFF | code: about 40k instructions, 455 functions |
| 0x2F1A0 | dispatcher with 81 entries (looks like K-line diagnostics) |
| 0x38000–0x3FFFF | working dataset, Nissan 7F405; DPP0/DPP1 = 0x0E/0x0F |

ROM routines (same addresses as on the Frontera):

| ROM | Purpose |
| --- | --- |
| `20D6` | 2D map interpolation (`0CDC` on the EDC15VM+) |
| `20AC` | 1D curve interpolation (`0CB2` on the EDC15VM+) |
| `0276` | stack overflow handler |
| `07B4` | task exit |
| `26FC` | metering position controller (receives setpoint `FC56`) |

**Process table:** 0x383F6, 60 entries of 10 bytes. Same format as on the EDC15VM+ but without a separate segment for the second function.

## Two datasets

- **0x38000–0x3FFFF (7F405)** is the one the code uses: `DPP0 = 0x0E`, `DPP1 = 0x0F` at startup.
- **0x00000–0x07FFF (7F406)** has the same layout and differs in 812 bytes, mostly the “fuel → metering” map (0x063E0) and two rpm × fuel maps (0x07722, 0x079E6). No code was found that switches to it, and the CPU sees ROM at these addresses, so it is most likely unused (an inference, not verified).

The last 4 bytes of each dataset (0x07FFC and 0x3FFFC) differ and look like checksums. The algorithm has not been identified yet.

## Comparison with the EDC15VM+ (1037362084)

The code was compared function by function using instruction sequences without addresses:

- 162 functions of 550 have a match in 084; 24,125 of 27,330 instructions align in the matched functions.
- Key functions match, the fuel ceiling even keeps process number #25:

| Function | 084 (CPU addr.) | 550 | Similarity |
| --- | --- | --- | --- |
| Fuel ceiling (#25) | 0x98D3A | 0x1D522 | 0.71 |
| Driver demand | 0x9C708 | 0x20166 | 0.47 |
| Fuel coordinator | 0x9A7E8 | 0x1E26A | 0.72 |
| Final and injection quantity | 0xAE798 | 0x2A03E | 0.74 |
| Metering setpoint | 0x9EF38 | 0x14A26 | 0.63 |
| Fuel temperature correction | 0xAFBCE | 0x1709A | 0.57 |

- **Variable mapping** derived from the aligned code (1997 variables with confidence ≥ 0.9), for example: rpm `F948` → `FC3A`, final fuel `F944` → `FC36`, ceiling `F98C` → `FCBA`, pedal `C0AA` → `C1D0`, atmospheric pressure `C112` → `C234`. Check: of 22 map axes in 084, 20 variables were found and all 20 land exactly on the axis IDs of 550.
- **Main difference:** the metering position controller is in ROM. The flash computes setpoint `FC56` (equivalent of `F964`) with the same formula and passes it straight to `CALLS 00:26FC`. There is no PI controller in the flash and no PWM/CAPCOM2 writes, so the controller gains cannot be changed from the flash. For tuning this does not matter: the whole fuel chain up to the metering setpoint is the same as on the EDC15VM+.

**Calibration** of the working dataset compared to 084: driver demand, rpm limiter, smoke limiter input, start fuel, fuel temperature correction and “fuel → metering” are identical. The smoke limiter differs in 69 of 208 cells: 550 cuts fuel harder at low air mass, 084 raised that zone (a later calibration with better low-air response).

Notes:

- ECM Titanium’s “[2]” / “[8]” in map names is the number of copies it edits at once: it writes to both datasets. After editing the metering map in Titanium, check that 0x3E3E0 changed by the same percentage and was not overwritten with the values of 0x063E0, because the two copies differ.
- ECM’s second “phase of injection” at 0x04842 (0x3C842 in the working set) (13×16) has no axis header (it starts right after the data of the 8×8 map at 0x047C2) and is referenced by no code or pointer table; the same block exists in 084 at 0x54D7E. Possibly read by ROM; its role cannot be verified from the flash.
- The **68 mg** fuel limit in the parameter block limits fuel independently of all maps listed by ECM.

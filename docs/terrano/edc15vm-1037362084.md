# Terrano 2.7 TDi — EDC15VM+, software 1037362084 / 1037362770

512 KB flash image. The two software versions share the same code; only calibration differs.

## Addresses

The flash is mapped at CPU address **0x80000** (visible from the code itself: `SCXT DPP2,#0024h` selects page 0x90000).

**CPU address = file offset + 0x80000.** Code addresses below are CPU addresses; map addresses are **file offsets**, as most tuning tools show them.

| CPU addresses | File offsets | Contents |
| --- | --- | --- |
| 0x00000–0x0FFFF | — | on-chip mask ROM (not in the dump); about 700 calls go there |
| 0x90000–0xBFFFF, 0xE0000–0xEFFFF | 0x10000–0x3FFFF, 0x60000–0x6FFFF | code: about 64k instructions, ~1030 functions |
| 0xD0000 | 0x50000 | dataset 1 (DPP0 = 0x34) |
| 0xF0000 | 0x70000 | dataset 2 (DPP0 = 0x3C) |

The code reads calibration through 16-bit addresses, so the same code works with either dataset; DPP0 selects which one. The two datasets are **not** duplicate copies: they differ, most likely variants for different Nissan part numbers (MT/AT). Tuning files change both.

## How the code works

- **Mask ROM**, as on the Frontera. Map interpolation: `00:0CDC` (2D) and `00:0CB2` (1D), called with R12 = map pointer, R13 = X, R14 = Y, result in R4. The scheduler and very likely the immobilizer are there too.
- **Process table** in the dataset at file offset 0x50446: 66 entries, two functions each. All 64 maps the code reads are reachable from it.
- **Sensors:** `CALLS 0A:FD58` reads an ADC channel, then a linearisation curve converts it to a physical value (e.g. the channel from `[1024h]` goes to `C002`, temperature in 0.1 K).
- **Map axis IDs** in map headers are RAM variable addresses, not axis types. The code often feeds a working copy of a variable to the axis, so the header ID alone does not tell what is on the axis.

## Fuel chain

| Step | Process | What it does | Output |
| --- | --- | --- | --- |
| Driver demand | #36 | Pedal `C0AA` is filtered, map **0x51E50** gives fuel = f(rpm, pedal). | `C0CC` / `C0CE` |
| Fuel ceiling | #25 | Smoke limiter **0x555F8**, rpm limiter **0x55296**, start fuel 0x55026, limp curve 0x56272 and others. | `F98C` |
| Coordinator | #32 | Larger of driver demand and two other sources (`C0C6` / `C0C8`), limited by `F98C`. Fuel→torque conversion 0x51838, packed into messages for another unit (possibly the automatic gearbox). | `C0C2` |
| Final fuel | #29 | `D7C8 = min(idle fuel, F98C)`, `D7C4 = min(C0C2, F98C − D7C8)`, `F944 = D7C8 + D7C4` (0 if injection enable `F993` is not set). Runs in a crank-synchronous task list. | `F944` |
| Injection quantity | #29 | `C44A` = `D7C8` + `D7C4` after the anti-jerk filter, **limited to 0…68.00 mg** (`[11E0h]+16h` = 6800). `C102 = C44A + D736 + C100`. | `C102` |
| Metering setpoint | #30 | Map **0x56920** (“injection (Ext.)” in ECM Titanium) converts `C102` and rpm into the pump metering position setpoint. | `F964` |
| Position controller | #41 | Error `F964 − F8AA` (actual position), limited to ±80; gains at **0x5AB3C** (800 and 700, P and I). 10-bit duty in `DE10` / `DE26`. | pump actuator |
| Monitoring | | `|F964 − F966|` above threshold sets fault 0x25DF or 0x25FB. | |

Terms of `C102`:

- `D736` — per-cylinder smoothness correction. The code is generic, with branches for 4, 5 and 6 cylinders (cylinder count in `D73C`).
- `C100` — fuel temperature correction: `0x563FC(rpm, F944) × (T − 50 °C) / 4096`, with T from `C006` clamped to −10…100 °C (thresholds at `[1372h]`). Hot fuel adds fuel, cold fuel removes it. `C006` is most likely the pump fuel temperature sensor (derived from logic, not from labelling).
- When `F944` drops to 0, `C102` is zeroed after a 50-cycle delay (`[11E0h]+18h`).
- With flag `C477` set, `C466` is used instead of the calculation (looks like an actuator test from a diagnostic tool).

So the quantity actually sent to the pump can exceed the ceiling `F98C` slightly, but not by more than 68 mg plus the temperature and cylinder corrections.

Further notes:

- A group of 12 maps at 0x52240–0x53B58 (axis ID `D976`) is not called directly from the code; its pointers are probably taken from RAM.
- A block at 0x54D7E matching ECM’s second “phase of injection” is not referenced by any code or pointer table.
- Process #46 uses 13 maps with axis `DA5A` and looks like injection timing; not verified.

Variables in `C36x–C3xx`, `C08x` and `F97x–F99x` are task-local and mean different things in different tasks.

## 084 vs 770

Same code, different calibration. Among the differences: fuel limiters (7000 vs 9000) and an rpm map (700 vs 900). One map moves: 0x57830 in 084 becomes 0x57832 in 770 with 11 rpm points instead of 10.

## Checksum

A known tuning file of 084 changes 4 bytes at **0x5AFFC** besides the maps, so this is very likely the checksum location. The algorithm has not been identified yet; recalculate with a known tool before flashing.

Opel Frontera B X22DTH · EDC15M

Bosch 0281001791GM 90589738ПО UU2M6S90_SCPU Siemens B58748 (C167, масочное ПЗУ)флеш 2×AM29F010, 256 КБ

Разбор стокового дампа по коду. Своим дизассемблером C166 разобрано около 53 тыс. инструкций. Найдено 96 стандартных точек входа задач и 78 дополнительных, 114 обращений к картам и 92 калибровочные карты. Каждая карта привязана к функции, которая её читает, и к переменным, которые идут на её оси. Ниже: как устроена прошивка, цепочки расчёта (подача, наддув, EGR, угол впрыска) и полный список карт с просмотром значений.

Поправки к распространённым определениям

Это то, что меняет Stage 1. Каждый пункт проверен по коду, который читает карту, а не по форме данных.

0x3C3AA = 2100

Уставка наддува обрезается константой 2100 мбар. После всех поправок задача 0x160C4 берёт min(уставка, [0x3C3AA]). Если поднять только карту наддува 0x3C496, выше 2100 уставка не пройдёт, пока не поднять эту константу. Рядом проверка отклонения: недодув больше +250 мбар или передув больше −150 мбар (параметры 0x3C3B4/0x3C3B6) даёт ошибку пути 0x1D.

0x3A308

Это уставка EGR по массе воздуха, а не угол впрыска. Titanium называет её «Phase of injection», но код говорит другое. Результат карты (C2E4) читает только задача 0x1EBB6. Она сравнивает его с массой воздуха с ДМРВ (C216) PI-регулятором, переворачивает выход кривой 100 %−x и при отклонении ставит ошибку пути 0x1E, а это P0400 (флаг 0x3AFEE). Участок 0x3A440–0x3A4D2 видимый код не читает: что там лежит, неизвестно, писать туда нельзя.

0x3CD30

Это не ограничитель наддува. Карта (обороты × подача, 20,3…33,2) входит в расчёт C214 → C252. Это значение уходит по CAN в ТНВД VP44 вместе с подачей. Значит, это запрос угла начала подачи. Как ограничитель наддува её не трогать.

0x3C8A2

Это не ограничитель подачи. Это пилотная скважность клапана наддува (обороты × подача, до 65,00 %). Она складывается с PI-регулятором давления в задаче 0x1F6B8.

0x3BB40 / 0x3BA70

Рабочие ограничители: «Injection at part throttle» и «Torque limiter 2». Копии 0x3B55A («Injection ext») и 0x3B8EA («Torque limiter 1») подмешиваются только с коэффициентом из кривой 0x3B926. В стоке она вся нулевая, так что на подачу эти копии не влияют. Править нужно рабочую пару.

Как работает код

Задачи

Все расчёты разбиты на задачи, которые вызывает планировщик из ПЗУ. 96 задач начинаются стандартным прологом mov r0,[0040h]; sub r0,#кадр; mov [r0],[FD86h], то есть выделяют кадр в своём стеке (вершины стеков лежат по 0x3803C–0x38042). Ещё 78 точек входа начинаются сразу с проверки cmp r0,[FD86h]. Выход из задачи идёт через jmps 00:07B4, переполнение стека через 00:0276. Таблица порядка задач лежит в ПЗУ, поэтому частоту и порядок вызова по дампу не восстановить.

Шаблон задачи

Сначала задача копирует нужные глобальные переменные в свою рабочую область (C0FA–C126, FC66–FC6A), считает, а результат пишет в одну-две глобальные переменные. Промежуточные значения задача дублирует в переменные мониторинга DCxx–DExx. Именно их адреса стоят в заголовках карт как «ID оси», поэтому в карте наддува Y = DD94 = C1EC + C1D0.

Карты

Заголовок: [ID X][nx][X…][ID Y][ny][Y…][данные]. Данные лежат построчно по X: индекс = x·ny + y. Код берёт адрес карты не напрямую, а из таблицы указателей. Пример: mov r12,[100Ch] читает 0x3900C → 0x446E → карта 0x3C46E. Затем r13=X, r14=Y и calls 00:20D6, результат в r4.

Ошибки

Все ошибки регистрирует calls 01:4002: r2 = (путь<<8) | ~бит, r1 = указатель на 8-байтовую запись дебаунса. У каждого пути есть заголовок с P-кодом и флагом включения. Например, путь 0x1E: P0400, флаг 0x3AFEE.

0x160C4

y = C1EC + C1D0. База (обороты, y). На высоте к ней прибавляется (обороты, y) с весом (атм.): вес 100 % при 750 мбар и ниже, 0 % от 950 мбар. Потом коэффициент по температуре , динамическая добавка через ПЗУ 22F2, добавка (нули). Результат ограничивается: не ниже 0 и не выше [0x3C3AA] = 2100.

→ C224 уставка наддува
0x1F6B8

Регулятор. Ошибка = C224 − C220, на неё P-звено (ПЗУ 21A2) и I-звено (21C4). К ним прибавляется пилот (обороты, y), результат ограничивается 0…65,00 % (0x3C3F2/0x3C3F6). Контроль отклонения работает только в окне и при допустимых температурах и давлении: недодув больше 250 мбар даёт бит 4 пути 0x1D, передув больше 150 мбар даёт бит 5.

EGR замкнутый контур по массе воздуха

0x15C84

ДМРВ: два отсчёта АЦП (C00C, C00E) → характеристика → среднее → деление на обороты → поправка . Проверка правдоподобия даёт путь 0x0B (P0100).

→ C216 масса воздуха, 0,1 мг/такт
0x1E772

Уставка: (обороты, C1EC+C1D0), плюс поправки по атм. давлению , по температуре и по ОЖ (на холодном моторе до +545 мг, то есть EGR закрыт). Ещё есть поправка по отклонению наддува (, в стоке нули). Ограничения берутся из блока 0x3A2A0.

→ C2E4 уставка массы воздуха
0x1EBB6

PI-регулятор ПЗУ 2430 (параметры 0x3A6AC, 0x3A6B6, 0x3A6C0) по ошибке C2E4 − C216. Выход переворачивается кривой (100 % − x). Режимы C9D8 подставляют фиксированную скважность из блока 0x3A68A: низкие обороты, большая подача, холодный мотор, ошибки датчиков. Контроль отклонения работает в окне , это путь 0x1E (P0400).

→ скважность клапана EGR

Как держать клапан закрытым программно, описано в docs/frontera-x22dth/tuning-notes.md. Физическая заглушка, где её можно поставить, надёжнее всего.

Угол начала подачи в VP44 по CAN

0x2C544

Холодный старт: (обороты, подача) × вес по ОЖ . Высота: × вес по атм. давлению . Сумма ограничивается (16,00), потом прибавляется ограниченный C210.

→ C20E поправка угла
0x1854C

База (обороты, подача), плюс поправка по температуре (обороты, C242), плюс , C20E и смещение 0x3CB4E. Потом ограничение через ПЗУ 2756. Второй канал (, ) в стоке нулевой.

→ C214 → C252 и C212 → C250, дальше в 0x12F8C → ТНВД

Роль подтверждена: значение уходит в пакет для ТНВД рядом с подачей. Единицы не подтверждены. 20,3…33,2 похоже на градусы × 100, но сам ТНВД может пересчитывать по-своему. Для Stage 1 этот угол лучше не трогать.

Карты, которые код реально читает через MAP2D/CURVE1D. «Уверенность» показывает, насколько надёжна подпись: H — роль видна по коду и значениям, M — по входам и выходам, L — догадка. Нажмите на строку, чтобы увидеть описание карты. Названия Titanium указаны в скобках.

Чего в дампе нет

  • Планировщика и порядка задач. Поэтому задачи перечислены по точкам входа, без таблицы с частотой вызова.
  • Прерываний: синхронизации по коленвалу, расчёта оборотов, приёма CAN на нижнем уровне. В видимом коде нет ни одного reti.
  • Внутренностей процедур ПЗУ. Интерполяция, PI-регуляторы, фильтры и регистрация ошибок видны только по аргументам и результатам.
  • Проверки иммобилайзера: она тоже в ПЗУ.
